Autoresearch: Tasks & Benchmarks

What the agents work on, how long evaluation takes, and where progress is getting harder.

Chonghe Jiang10 min read
On this page Algorithms & mathematics Software & systems Science & ideation

Algorithms & mathematical search

Task name Benchmark / source Description & eval time Recent progress & saturation
Polyomino packing Frontier-CS #0 Minimize the packing rectangle. Heavy: ~2–3 min for 70 cases. Still improving. Test-Time Communication reports a new best-known result; Fork-and-Flush finds further search gains. Guidance-TTT also advances the frontier.
Apple production planning AtCoder AHC058 Allocate machine investments. Heavy: ~5 min serial, 150 × 2 s. Small frontier gains. Guidance-TTT.
Job-shop scheduling Frontier-CS #46 Minimize schedule makespan. Light: ~20–40 s for 15 cases. Agent results available. Recent experiments evaluate this suite; comparison with specialized scheduling methods remains limited.
AHC014 / RectJoin AtCoder; Frontier-CS #159 Add valid rectangles on a dot grid. Heavy: ~1–5 min for 30 cases; ~10–15 min for 75. Recent agent gains. Fork-and-Flush and Forgetting improve agent baselines; case sets and budgets differ.
Toroidal string placement AHC004; Frontier-CS #150 Fit strings into a wrapping grid. Heavy: ~15–20 min for 100 cases. Recent agent gains. Search improves agent solutions; comparisons with the strongest contest solutions require matched limits.
Ice-rink routing Frontier-CS #171 Visit targets using moves, slides and block edits. Heavy: ~10–15 min for 75 cases. Recent agent gains. Forgetting and Fork-and-Flush improve baselines; 100 is a reference score, not a ceiling.
Sphere packing Frontier-CS #48 Pack equal spheres into a cube. Light: ~20–40 s for 15 cases. Small recent gains. Agent experiments report improvements on this suite; difficulty varies with the number of spheres.
Mobile relay layout Frontier-CS #307 Place relay hubs and assign sensors. Mixed: ~30–60 s for 10 cases. Narrow score range in one study. Reported results cluster at 72.73–72.82; this alone does not establish saturation.
Order-add EdgeBench Optimize a permutation through a cost oracle. Light/Mixed: ~seconds–minutes to score; solver runs can take hours–days. Grader issue affects comparisons. An independent audit finds best-submission selection errors that can hide later improvements.
Circle packing, n = 26 AlphaEvolve-style task; CCTS Maximize summed radii. Light final check, ~sub-second–seconds; Mixed optimizer run, ~seconds–minutes. Hard to improve meaningfully. TTT-Discover, ThetaEvolve and SimpleTES repeatedly reach ≈2.635983. Tiny differences require matched feasibility tolerances.
Arithmetic Kakeya CCTS mathematical suite Optimize an entropy-based construction. Light check, ~sub-second–seconds; Mixed search, ~seconds–minutes. Diminishing gains at the frontier. The matching four-slope entropy record improved in 2026, but the latest increments are around 10⁻⁹–10⁻¹¹.
Heilbronn’s triangle CCTS mathematical suite Place 11 points to maximize the smallest triangle. Light check; Mixed search, ~seconds–minutes. Hard to improve at n = 11. MLEvolve and AlphaEvolve effectively tie at 0.03652989; the Arena leaders reproduce it.
Squares in a square CCTS mathematical suite Fit non-overlapping squares with maximum summed side length. Light check; Mixed search, ~seconds–minutes. Depends on the instance size. Recent theory studies the same side-length objective; empirical comparisons for CCTS’s exact task remain limited.
Synthetic concept search CCTS controlled environment Mutate concept sets and sum their utilities. Light: ~sub-second scoring. Not applicable. The utility landscape is constructed by CCTS; it has no external research frontier.

Software & systems

Task name Benchmark / source Description & eval time Recent progress & saturation
VLIW kernel Anthropic performance take-home Schedule instructions on a simulated machine. Light: ~1–30 s for correctness and cycle scoring. Headroom beyond paper baselines. Public runs below 1,000 cycles beat the ≈1,112-cycle SLA result; test variants must match.
LLM-SQL cache optimization Frontier-CS research track Reorder data to improve prefix-cache reuse. Mixed: ~10 s–3 min; deterministic scoring, no LLM inference. Plateau within one study. Several methods share a 27.05 best score; broader evidence of saturation is limited.
libexpat → assembly; Git → Zig; Dart → Haskell; Lua compiler FrontierSWE Implement or port software and run functional suites. Heavy: ~1–30 min per build-and-test cycle. Mixed. SLA brings Lua near full coverage; FrontierSWE V2 changes and expands the suite, so old scores do not establish broad saturation.
GPU kernels SOL-ExecBench Compile, verify and time kernels. SLA’s #1/#58/#210: Mixed, ~tens of seconds–minutes. DuoDiscover’s full evaluator: Heavy, 2–60 min. Still improving overall. SLA and DuoDiscover find gains. Difficulty varies by kernel; a Triton plateau is not a hardware ceiling.
TriMul TTT-Discover / GPUMode Optimize triangle multiplication. Heavy: ~minutes estimated; 520 s timeout. Narrow frontier gaps. Guidance-TTT.
Lasso path TTT-Discover Accelerate regularization-path solving. Mixed: ~seconds–minutes estimated, compilation and 17-case verification. Recent gains remain. Guidance-TTT.
Repository speedups FormulaCode-V Optimize scientific Python repositories. Heavy: 7 min–6.8 h. Still improving. FormulaCode exposes unresolved expert gaps; DuoDiscover improves a selected subset. Their aggregate scores are not interchangeable.
Workload speedups SWE-fficiency-Lite Speed up repository workloads without breaking tests. Heavy: 3–93 min. Still improving. PerfAgent raises expert-matching patches from 26% to 74%; DuoDiscover reports further workload speedups.
JAX kernels JAXBench Optimize TPU kernels. Heavy: 7–32 min. Still improving. JAXBench leaves gaps to tuned Pallas kernels; DuoDiscover reports newer gains. Hardware and subsets differ.
Inference kernels TPU-Inference Optimize model inference kernels. Heavy: 1–8 min. Recent gains over tuned baselines. DuoDiscover improves tuned Pallas kernels on this suite.
Attention kernels Flash Attention 4 Optimize B200 attention configurations. Heavy: 4 min. Still improving despite mature baselines. AVO beats FA4 by up to 10.5% on selected B200 shapes; DuoDiscover also finds gains.
LLM serving vLLM case study Balance serving latency, power and throughput. Heavy: 85 min. Substantial gains on the tested workload. DuoDiscover improves serving performance; results depend on the vLLM version and traffic mix.
Offloaded MoE inference FreeToken case study Optimize single-GPU inference with host-resident weights. Heavy: 70 min. Workload-specific results. DuoDiscover studies one FreeToken configuration; hardware and model choices affect comparisons.
Database execution SQLite case study Optimize engine performance with correctness checks. Heavy: 10 min. Recent workload gains. DuoDiscover improves SQLite performance on its tested workload.
Compression zstd case study Reduce instructions while preserving output bytes. Heavy: 15–25 min. Recent workload gains. DuoDiscover improves byte-preserving zstd execution; broader codec results optimize different objectives.
CPU data prefetching DPC4 / ChampSim Evaluate prefetcher designs across simulation traces. Heavy: up to 28 h on the study’s cluster. Still improving, with costly gains. ArchAgent v2 beats the DPC4 champion by 0.3% overall; DuoDiscover explores further designs.

DuoDiscover’s timings above are reported full-evaluation measurements on its hardware. Its proxies are much lighter: median 16 s on sampled SOL-Exec kernels and 40 s on sampled SWE-fficiency tasks. These are different evaluators, not faster runs of the same full test.

Scientific inference, learning & ideation

Task name Benchmark / source Description & eval time Recent progress & saturation
Structured-LWE recovery Frontier-CS 2.0 Recover valid secrets. Mixed: ~seconds–minutes for witness checks; Heavy: minutes–hours or more for solver experiments. Unsolved instances remain. Fork-and-Flush and SLA leave instances unsolved; comparisons with specialized attacks remain limited.
Borden source inversion EdgeBench Infer a groundwater contamination source. Heavy: ~minutes–hours, including forward simulation and inversion. Formulation affects score interpretation. A recent audit finds unstated physics conventions. Score gains can reflect learning the checker rather than better inversion.
tinyCIFAR Fork-and-Flush custom task Trade classifier accuracy against compressed size. Heavy: ~minutes–hours per training trial. Limited independent evidence. This custom accuracy–size objective has little independent replication; ordinary CIFAR accuracy records measure a different objective.
nanochat training nanochat-autoresearch Improve validation loss under a fixed training budget. Heavy: ~5–7 min, including 5 min on H100. Still improving. Forgetting, GitSwarm and rekursiv.ai report gains; H100 and B200 scores need separate comparisons.
Symbolic regression LLM-SRBench subset in MIRA Recover equations from data. Light: ~1–10 s to score an expression; fitting adds cost. Still improving. PTB-Search and HarnessSR improve LLM-SRBench results. Near-perfect fit in MIRA does not imply exact equation recovery.
Physics discovery DiscoverPhysics adaptation in MIRA Design experiments and infer hidden laws. Mixed: ~seconds–minutes per simulation and score. Not broadly saturated. The original benchmark still has unsolved worlds; MIRA uses an adaptation, so scores cannot be pooled.
Causal graph recovery BNLearn adaptation in MIRA Infer a DAG using observations and interventions. Light: ~1–10 s for graph scoring. Many full-credit runs in this adaptation. MIRA’s results suggest limited headroom on some instances; broader replication remains limited.
CPU architecture search HillClimbBench-CPU Train each proposed neural architecture from scratch. Heavy: ~minutes–tens of minutes per trial. Limited independent evidence. HillClimbBench-CPU is a custom task distribution with few independent results.
RMT / Loop Transformer design HillClimbBench-RMT / -Loop Revise architectures and compare training loss. Heavy: ~minutes–hours per trial. Still improving in recent studies. Both MIRA and GitSwarm improve starting designs; compare training budgets before ranking results.
Olympiad proof generation IMOProofBench Advanced Grade a proposed proof. Mixed: ~tens of seconds–minutes per model judgment. Saturated for strong-agent solve rate. MIRA and GitSwarm both report all 30 solved with GPT-5.5 under their grading protocols.
Research proposal generation Svalbard Idea Vault / IdeaScientist Retrieve literature and judge novelty and quality. Mixed: ~30 s–5 min per review; no experiment execution. New evaluation; limited follow-up. IdeaScientist introduces this task; proposal ratings do not measure experimental success.
How the estimates are formed

For the Frontier-CS suites, a useful budget is number of cases × solver time per case, plus compilation and checking. The public configs give polyomino 70 × 2 s, job-shop and sphere packing 15 × 1 s, relay layout 10 × 4 s, AHC014 and p171 75 × 10 s, and p150 100 × 10 s. These estimate a solver that uses most of its allowance, not an observed average. Faster solvers, fewer cases and parallel workers reduce wall time; the papers may use different subsets.

Other ranges are order-of-magnitude judgments from the task: direct numerical checks are cheap, while compilation, repeated test workloads, simulations and retraining add cost. Unbounded numerical search has no fixed duration. MIRA’s task protocols, for example, distinguish graph scoring from training each architecture afresh. Model-judged tasks include the evaluator’s LLM calls. A larger judge or a slower service can push them beyond the range shown.
